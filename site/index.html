Ingredients

  • .actrc · one image per runs-on label
  • .secrets · gitignored, names your workflows use
  • .vars · for ${{ vars.* }}
  • .github/act/pull_request.json · the event

Then, in any repository: “set up local CI for this repo”.

Why I made this

My company's GitHub organisation is on the free plan. One month it ran out of Actions minutes, and from then on every job on its private repositories failed in three or four seconds with zero steps executed. Nothing was wrong with the code. GitHub had simply stopped cooking.

Running workflows locally with act was the obvious way out. The trap is the next step: someone copies the CI steps into a ci-local.sh, and from that day there are two pipelines that slowly disagree. I watched an agent do exactly that when I asked it to set up local CI without guidance.

So the rule of this skill is simple: the workflow file stays the only recipe. act cooks the real YAML. The only local things are the ingredients act needs, and a drift check tells you when they no longer match what the workflows ask for.

— Philippe Matray

Method

  1. Ask for it

    In the repository you want to run locally, tell Claude Code:

    set up local CI for this repo so I stop burning Actions minutes

  2. Check the ingredients

    The skill reads every workflow, then runs its drift check: which runs-on labels have no image, which secrets and vars are missing, which jobs only GitHub can run. It prints names, never secret values. This is real output, on a copy of TaLibStandard right after two jobs were added to its workflow:

    $ python3 act_drift.py
.github/workflows/ci-cd.yml  on=push,pull_request,workflow_dispatch
  runs-on=macos-14,macos-latest,ubuntu-24.04,ubuntu-latest,windows-latest
  note  GitHub-only (act can't run): macos-14, macos-latest, windows-latest
  note  id-token: write (OIDC) — guard publish/deploy steps with !env.ACT

DRIFT:
  .github/workflows/ci-cd.yml: unmapped: ubuntu-24.04
  .github/workflows/ci-cd.yml: missing secrets: CODECOV_TOKEN
  .actrc sets artifact-server-path: act ignores host-path flags
         in a project .actrc
  .actrc forces linux/amd64 on Apple Silicon: breaks node after setup-* actions
         and runs ~4.5x slower — run natively

    Lines wrapped for width. Exit code 1 while anything drifts, 0 once it is clean.

  3. Cook the real workflow

    act runs the jobs of .github/workflows/*.yml in Docker. Every failure is sorted into one of three: a real failure (fix the code), an act limitation (see the notes below), or a missing ingredient (fix the local files). Only the second can justify touching a workflow, and only with a guard that changes nothing on GitHub, after asking you.

  4. Re-check when the recipe changes

    Changes flow one way: workflow file first, local files after. Run the drift check again after any workflow edit, or let a pre-push hook run it with act before each push. A red build caught here is a GitHub run that never happens.

The part that costs you

Running act saves money only if GitHub runs less, and that lever is yours. Branch protection, required checks and automerge only read GitHub's checks: a green run on your Mac is invisible to them. The skill never changes your triggers. It lays out the options, gentlest first:

  1. GentlestCancel superseded runs with concurrency: cancel-in-progress.
  2. CheapSkip CI on docs-only changes with paths-ignore.
  3. BiggerMove heavy jobs (full matrix, macOS) to nightly or manual triggers.
  4. Last resortDrop the pull_request trigger, and accept that PRs carry no GitHub verdict.
